# Migration Guide: 0.11.x to 0.12.0-rc.12

HardKAS 0.12.0-rc.12 introduces strict **Execution Worlds** to fix the ambiguity between simulated runs and real local network runs. This requires a few changes to how you write scripts and use the CLI.

## 1. Simulated vs Simnet Ambiguity Resolved
In 0.11, "simnet" was often conflated with the in-memory JavaScript Simulator. In 0.12.0-rc.12:
- **Simulator**: The JS-based, in-memory, synchronous transaction simulator (`mode: "simulator"`).
- **Localnet (simnet)**: A real local Kaspa node (`rusty-kaspad`) running on the `simnet` network with real Proof-of-Work and Docker orchestration (`mode: "localnet"`).

If you were using `simnet` to refer to the Simulator, update your code to use the `simulator` execution mode.

## 2. CLI Namespaces
The CLI now strictly partitions commands based on the execution world.
- Use `hardkas simulator account create` and `hardkas simulator fund` for synthetic testing.
- Use `hardkas localnet start --profile <name>`, `hardkas localnet account create`, and `hardkas localnet fund` for real local node testing.
- The generic `hardkas accounts fund` is deprecated and will route to the synthetic logic with a warning.

## 3. Profiles are Mandatory for Localnet
You can no longer run `hardkas localnet start` without specifying a profile. 
You must explicitly declare the profile to ensure deterministic infrastructure:
```bash
hardkas localnet start --profile toccata-v2
```

## 4. Default Config Accounts Removed
`alice`, `bob`, and `carol` have been removed from `DEFAULT_HARDKAS_CONFIG.accounts`.
HardKAS still provides deterministic generated accounts for `alice`, `bob`, and `charlie` out-of-the-box (in `.hardkas/dev-accounts`), but they are no longer injected into the user config to prevent `CrossWorldAccountCollisionError` between local disk accounts and synthetic configuration accounts. 

## 5. Execution Compatibility Enforcement
All transaction lifecycle commands now enforce strict execution compatibility. 
- You cannot verify, sign, or replay a transaction plan in an execution world that does not match its `mode` (e.g., you cannot sign a `mode: "simulator"` plan with a real Kaspa node).
- Synthetic accounts (`kaspa:sim_...`) can no longer interact with Localnet or RPC. `hardkas localnet fund` will reject synthetic accounts. You must generate real `kaspasim:` accounts for Localnet.
