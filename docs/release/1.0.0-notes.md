# HardKAS 1.0.0 — release notes

**Status: version set in the repository; not yet published on npm.** The npm status of this release is recorded here when it is published (the last published candidate is [0.13.0-rc.3](./0.13.0-rc.3-notes.md)). The [CHANGELOG](../../CHANGELOG.md) has the full list.

1.0.0 is the first stable release. "Stable" is scoped by [Version Guarantees](../status/versioning.md): the boundaries listed there as stable (artifact identity and hashing, the local simulated state, the core transaction lifecycle, the Toccata v2 localnet baseline, the release claims) change only with a major version. Preview and experimental surfaces, and every command whose `--help` does not end in `stable`, may still change in a minor release. Stable does not mean ready for production custody, and **mainnet stays blocked by policy**: no flag, option or configuration enables it.

## What is new since 0.13.0-rc.3

- **The node must say which network it serves.** A node that answers `getServerInfo` without a network, or refuses the question, is refused (`NODE_NETWORK_UNKNOWN`) even when the caller named no expected network. Before, a read without an expected network went on.
- **Address reads are judged before any connection.** `accounts balance` and `rpc utxos` refuse an address whose prefix is not the network's (`ADDRESS_NETWORK_MISMATCH`), and a mainnet-type address without a network, before a socket is opened.
- **Dev server: "local" is decided on the socket.** The peer address decides, not the `Host` header; the `Host` check stays as the DNS-rebinding defence. A bind host that is not this machine needs `--unsafe-external` (`DEV_SERVER_HOST_NOT_LOOPBACK`), a `HARDKAS_DEV_TOKEN` shorter than 32 characters is refused (`DEV_SERVER_TOKEN_TOO_WEAK`), and `?token=` is accepted only on the SSE stream route.
- **`hardkas up --json`** prints one JSON document (status, url, token); the server's banner and logs go to stderr.
- **The fixture signer refuses every spelling of mainnet** (`kaspa-mainnet`, `Mainnet`, …), not only the exact word.
- **`query dag` reads the simulated ledger's DAG** (`.hardkas/localnet.json`), the one `dag status` shows; without a DAG it still refuses (`DAG_DATA_UNAVAILABLE`) instead of answering "all clear".
- **A plan whose header disagrees with its outputs is refused** (`TX_PLAN_HEADER_MISMATCH`), and `artifact verify` states that a record's origin is not authenticated (`ARTIFACT_ORIGIN_NOT_AUTHENTICATED`).
- **Docker calls have a time limit**, so a stuck Docker no longer blocks a run for hours.
- **Less surface.** `@hardkas/client`, `@hardkas/react` and `@hardkas/simulator-adapters` were removed from the workspace (private, with no consumer; any version an earlier release put on npm is untouched, and deprecating it is the owner's decision). The release publishes 18 packages.

## If you used 0.13.0-rc.3

- **Dev server:** pass `--unsafe-external` to bind a host that is not loopback; set `HARDKAS_DEV_TOKEN` to 32 or more characters or leave it unset; send the token as `Authorization: Bearer <token>` everywhere except the stream route.
- **A node that does not state its network** is now refused. Real rusty-kaspad nodes always state it.
- **Version strings:** every manifest and the runtime report `1.0.0`. `hardkasVersion` is not part of any content hash, so no artifact identity changes.

## What is not covered

- **KCC-20 on a node (K5)** runs in CI against the pinned reference checkout; it was not run locally for this release.
- **Kastle** does not sign payments (`signTx`, not `signPskt`); KasWare and Kaspire are the verified wallets.
- **Coverage:** the hermetic gate does not run the `silverc`, `simnet` and Docker levels; those run in their own CI jobs.

## Install

```bash
npm install --save-dev @hardkas/cli@1.0.0
npm install @hardkas/sdk@1.0.0
```

Use the exact version.
