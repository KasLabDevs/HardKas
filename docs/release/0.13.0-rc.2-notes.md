# HardKAS 0.13.0-rc.2 — release notes

**Status: candidate, not published.** npm still has `0.13.0-rc.1` (`latest` and `next`). Everything below describes the code on `develop`; the [CHANGELOG](../../CHANGELOG.md) has the full list.

## What is new

- **Mainnet hardening for a future opening.**
  - Unplanned mainnet sends are refused permanently (`MAINNET_UNPLANNED_SEND_REFUSED`).
  - `tx sign --allow-mainnet-signing` is removed.
  - `HARDKAS_KASPAD_IMAGE` must be pinned by digest everywhere a node runs from it.
  - PSKT signing checks the signer's own network and node instead of the session file's word.

  Mainnet stays locked down in this release line: nothing signs, sends or connects to it.
- **Evidence does not expire.** `artifact verify` no longer fails an intact artifact for its age. Age matters only before signing or sending.
- **Safer fees by omission.**
  - A v1 contract spend or covenant transition that leaves its remainder as fee is capped unless the caller asks for more.
  - A payment the node no longer holds names the way out (`TX_ALREADY_SUBMITTED`).
- **ZK (experimental).**
  - The receipt's verifier parameters are checked.
  - A second, HardKAS-made receipt; its proof was spent on Testnet-10 with test funds, with the node's rejections of invalid spends recorded.
  - Public receipts no longer get proof-only locks on public networks.
- **`hardkas localnet seed` (alpha).** Exact balances for dev accounts from a localnet treasury whose key is public by design (simnet only).
- **Fixes:**
  - `tx wait --address` with spent outputs;
  - escrow refund retries;
  - `replay verify` on real-node sends;
  - `rpc doctor` and `doctor` exit codes;
  - `tx send --target`;
  - `tx wait --timeout 60s`.
- **Release safety.** Release tarballs carry committed files only, and the audit report records each tarball's sha512.

## Install (once published)

```bash
npm install --save-dev @hardkas/cli@0.13.0-rc.2
npm install @hardkas/sdk@0.13.0-rc.2
```

Use the exact version. The `rc` dist-tag is not moved by this release line.

## Before publishing

For the commit that will be published (none is yet):

- [ ] CI green on Ubuntu, Windows and macOS for that exact commit: canonical gate, release and docs gates, `static-checks`, test levels (silverc, SilverScript runner, simnet), Docker suites and examples. A green run of another commit does not count.
- [ ] In a fresh clone of that commit: `pnpm install --frozen-lockfile`, then `pnpm release:build`, then `node scripts/check-release-tarballs.mjs --pack --dir <new folder> --report <file>`, without `--allow-dirty`. Expected: 22 tarballs, no finding, `publishable: true`.
  - `--pack` refuses a dirty or other-commit build, a dirty tree, an untracked file and a non-tarball folder.
  - Never publish tarballs packed from a working tree, or from a run with `--allow-dirty`.
- [ ] `pnpm version:check` and `pnpm check:licenses` pass on that clean install.
- [ ] The maintainer logged in to npm again (`npm login`) before publishing.
- [ ] Exactly the 22 audited tarballs are published with `npm publish <tarball> --tag next`. The sha512 npm records for each one equals the `integrity` in the audit report.
- [ ] Decided: when to move `latest` to `0.13.0-rc.2`.
