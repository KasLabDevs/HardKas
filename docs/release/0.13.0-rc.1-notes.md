# HardKAS 0.13.0-rc.1 · release notes

> **Published on npm on 2026-11-10.** The 22 packages are on npm at `0.13.0-rc.1`, built from the commit tagged
> `v0.13.0-rc.1`. The npm tags `latest` and `next` both point to `0.13.0-rc.1`. [Before publishing](#before-publishing)
> records the checks that were made.

HardKAS is local-first developer tooling for Kaspa L1: a CLI (`hardkas`), a TypeScript SDK and test helpers for planning,
signing, sending and verifying transactions against a node you control, with evidence you can re-check offline. This
candidate adds the transaction v1 covenant engine, typed network identity and three-level `artifact verify`, locks
mainnet out entirely, and publishes 22 packages.

## Mainnet: total lockdown (NO-GO)

This release is **not** for Kaspa mainnet, and HardKAS does not touch it at all.

- **No connection to mainnet, reads included.** No command or SDK call contacts a mainnet node: no RPC read, no
  balance, no plan, no wait, no status look, no diagnostic. The endpoint authority gives a mainnet network no endpoint,
  and the RPC transport refuses it before connecting: `MAINNET_CONNECTION_DISABLED`.
- **No signing and no broadcast on mainnet**, offline signing included: `MAINNET_SIGNING_DISABLED` and
  `MAINNET_BROADCAST_DISABLED`, raised before any connection, signer call or record. HardKAS builds no complete mainnet
  ZK spend and no mainnet ZK lock address.
- **No mainnet key from the CLI's key commands**: `accounts real generate`, `accounts real import` and
  `kaspa wallet create` (with or without `--show-private-key`) refuse mainnet with `MAINNET_SIGNING_DISABLED` before any
  key exists.
- Every spelling counts (`mainnet`, `mainnet-<n>`, `kaspa`, `kaspa-mainnet`, any case), and so does a config entry that
  declares one (an alias such as `prod`).
- **No flag opens it.** `allowPublic`, `experimental`, `allowMainnet`, `--allow-mainnet*`, `HARDKAS_*` variables and the
  configuration have no effect: the policy is two constants in `@hardkas/core` (`MAINNET_CONNECTIONS_ENABLED` and
  `MAINNET_TRANSACTIONS_ENABLED`, both `false`).
- **The only mainnet operation is offline:** `hardkas artifact verify` of a mainnet record checks its integrity and
  contacts no node (network level `NOT_CHECKED`, reason `MAINNET_NETWORK_CHECK_BLOCKED`).
- The one limit no client can remove: an endpoint declared as another network (or a raw `--url`) is known to be mainnet
  only from its node's own identity answer. The transport asks that once, before anything else, and closes the
  connection when the node says mainnet; nothing else is asked.
- CI has no mainnet endpoint, key or token. Unblocking mainnet needs an independent audit, complete validation and an
  explicit decision of the maintainer. No test result of this candidate is a security guarantee for mainnet.

## What was tested, and where

The L1 behaviour below was checked against a real rusty-kaspad v2.1.0 node (image pinned by digest), not against the
simulator. Each network has its own evidence; one network does not stand in for another.

| Network | What ran | Result |
| :-- | :-- | :-- |
| simnet (own Docker node) | payments, double spend, re-send without a local record, Silver deploy and spend, covenant genesis and transitions (1:1, 1:N, N:M, terminating), KCC-20, consensus vectors | accepted or rejected as the node decides; records `CONSENSUS_CONFIRMED` |
| devnet (own node and miner) | CLI: payment, Silver deploy and spend, covenant genesis and 1:1 transition. SDK (the v1 covenant engine, `covenant-topologies-node-devnet.simnet`): 1:N (one input to three continuations), N:M (two to two, leader and delegate), terminating (1:1, then 1:0) and the signed KCC-20 N:M transfer | CLI: `CONSENSUS_CONFIRMED`. SDK: 10 transactions accepted and mined (9 checked `CONSENSUS_CONFIRMED` with `hardkas artifact verify --require consensus`; the 10th, a raw send, read from the node's UTXO index), and 12 invalid variants rejected by the node; all 22 verdicts match simnet's |
| testnet-10 | read-only in this candidate: verification of earlier payments | `NETWORK_OBSERVED` and `CONSENSUS_CONFIRMED`; **no testnet transaction was sent for this candidate** |
| mainnet | nothing | no connection, no key, no signing, no broadcast; only offline `artifact verify` |
| simulated (in-memory) | the examples and the unit level | never counts as node evidence |

On the CLI, the covenant commands were run against a real node for 1:1 only; 1:N, N:M, terminating and KCC-20
topologies were run through the SDK. The devnet runs used a single node and a single miner: no peers, no reorgs, no
parallel blocks. There is no TN10 evidence for covenant topologies other than 1:1. TN10 uses the same lifecycle and the
same upstream primitives; verifying this candidate on a public network is still pending.

Not tested: absolute lock times (CLTV; HardKAS does not build them) and spending from ECDSA addresses (the signer is
Schnorr only). The simulator's `WrongMass` rule stays UNVERIFIED. The SilverScript runner (cli-debugger) is a local build
of the pinned commit and is UNVERIFIED as a tool: its verdicts are never consensus evidence.

## Breaking changes

The full list, with migrations, is in [CHANGELOG.md](../../CHANGELOG.md) (its Breaking section, the fixes of each
round and "Fixed after the surface audit") and [docs/migrations/0.12-to-0.13.md](../migrations/0.12-to-0.13.md). In
short:

- **Mainnet total lockdown** (above): connections and reads are refused too, not only signing and sending.
- **Node.js 24.22.1 exactly** for the packages that declare `engines`.
- **Artifact hash version 5.** Older artifacts are read with the `LEGACY` scope; re-issue them with
  `hardkas artifact migrate <path> --to 5`.
- **A node that does not report it is synced is refused** (`NODE_NOT_SYNCED`) by the commands that plan, send or wait,
  and by the SDK's `tx.send`.
- **`tx send` never sends a payment twice**: with a local record, or when the node already holds it, it answers
  `already-submitted` / `ALREADY_SUBMITTED` and sends nothing.
- **`--json` usage errors** are one `{ ok: false, code }` envelope with exit code 2; **`hardkas doctor` exits 1** when
  a check fails.
- **Unsupported constructions are refused with a code** (`ECDSA_SPEND_NOT_SUPPORTED`, `LOCK_TIME_NOT_SUPPORTED`).
- **`@hardkas/sdk` no longer installs `snarkjs`** (GPL-3.0): it is an optional peer. Without it the Groth16 checks
  return `ZK_ENGINE_UNAVAILABLE`, never a verified result.
- **`@hardkas/testing` covenant matchers** require node evidence by default.
- **The dashboard is retired**; local development runs on `@hardkas/dev-server`.
- **After the surface audit:**
  - step 1: two `exports` entries that resolved to nothing are gone (`@hardkas/kaspa-rpc/adapters`, the `"./*"` of
    `@hardkas/query`), and a misspelt dev-server variable is `ENV_UNKNOWN_VARIABLE` in `env check`;
  - step 2, honest results: `rpc compare` with no node reachable, a declined `lock clear`, the `query dag` views without
    data (`DAG_DATA_UNAVAILABLE`) and `localnet snapshot create --consensus-validated` now fail; `artifact create` and
    `programmability` records no longer claim validation or node evidence; options that do nothing say so
    (`OPTION_NO_EFFECT`); `-h` is the help again in `simulator start` and `sandbox` (the host is `-H`);
  - step 3, data protection: `config init|repair`, `dev init`, `accounts real init --force` (now needs
    `--discard-accounts`), `chaos` and `torture` no longer lose a configuration, backup, account or file; `dev tx send`
    sends on the simulated ledger and a local simnet only;
  - step 4, security: `accounts real generate|import` and `zk toccata build-scripts --address-network` refuse mainnet;
    the dev server signs for HTTP clients only with `HARDKAS_DEV_SERVER_AUTOSIGN=1`, and only on the simulated ledger or
    a local simnet (`DEV_AUTOSIGN_NOT_ALLOWED`); `node start` runs only an image pinned by digest
    (`NODE_IMAGE_DIGEST_REQUIRED`).
- **Pre-release round:**
  - 8 packages are no longer published (below);
  - the dev server's escrow routes `POST /api/escrows/:id/fund` and `POST /api/escrows/:id/sign` sign with its
    development accounts only with `HARDKAS_DEV_SERVER_AUTOSIGN=1` (HTTP 403 `DEV_AUTOSIGN_NOT_ALLOWED` otherwise);
  - `kaspa wallet create` refuses mainnet with `MAINNET_SIGNING_DISABLED`, with or without `--show-private-key`.

[docs/status/versioning.md](../status/versioning.md#published-packages): `@hardkas/cli`, `@hardkas/sdk`,
`@hardkas/testing`, `@hardkas/core`, `@hardkas/config`, `@hardkas/tx-builder`, `@hardkas/artifacts`,

These stay `private` in this release ([why](../status/versioning.md#not-published)):

- `@hardkas/l2` (until its API, dependencies and promises are reviewed) and `@hardkas/ext-l2` are not published, so
  `hardkas extension install l2` refuses with `EXTENSION_NOT_PUBLISHED` unless given a local tarball
  (`--from <tgz> --sha256 <hex>`);
- `@hardkas/pskt-native` (on hold: built from rusty-kaspa 2.0.1 crates, win32-x64 only, no guarantee);
- new in this candidate, the 8 packages no published package depends on: `@hardkas/client`, `@hardkas/react`,
  `@hardkas/wallet-adapter`, `@hardkas/simulator-adapters`, `@hardkas/plugin-local-indexer`,
  `@hardkas/plugin-rpc-backend`, `@hardkas/sync-daemon` and `@hardkas/storage-postgres`. They stay workspace packages
  that the monorepo's labs, reference apps and showcase apps use; this release publishes no version of them.

Every published package is MIT and ships its `README.md` and `LICENSE`. Third-party licenses of the published packages
are listed in [docs/status/dependency-licenses.md](../status/dependency-licenses.md): only the optional `snarkjs` and
its tree are copyleft.

## Experimental and out of scope

- `@hardkas/simulator` is an approximate model with known divergences from rusty-kaspa
  ([limitations](../status/limitations.md#the-simulator-is-an-approximate-model)). It is frozen in this release.
- The ZK tooling is local and experimental: HardKAS verifies proofs off-chain and claims no on-chain ZK verification.
- vProgs is inspect-only. HardKAS performs no bridge operations.
- Open items are listed under "Known open items" in the CHANGELOG and in
  [docs/status/limitations.md](../status/limitations.md).

## Install

```bash
# Node.js 24.22.1
npm install --save-dev @hardkas/cli@0.13.0-rc.1 @hardkas/sdk@0.13.0-rc.1
npx hardkas doctor
npx hardkas toolchain install kaspa-wasm
```

`latest` points to `0.13.0-rc.1`, so `npm install @hardkas/cli` without a version gets it too; the exact version keeps
the install fixed when a later version is published. `hardkas toolchain install` downloads the pinned official release asset and checks it, and every installed file,
against the pin; nothing that does not match is loaded. Add `snarkjs@0.7.6` only if you need the Groth16 checks and
accept its GPL-3.0 tree.
