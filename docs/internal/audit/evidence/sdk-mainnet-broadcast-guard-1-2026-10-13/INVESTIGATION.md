**Policy:** while HardKAS keeps mainnet transactions disabled, no high-level path signs or broadcasts on mainnet because `allowPublic` is set, an external signer is given, or `tx.send` is called directly. Reading and planning on mainnet stay allowed; testnet with `allowPublic` stays allowed. `allowPublic` is not `allowMainnet`.

**Reviewer decisions (GO 2026-10-13):**
- **D-MG-1:** `sdk.rpc` (kaspa-rpc) stays a low-level API without the product policy, and is never presented as a safe way to broadcast on mainnet.
- **D-MG-2:** an explicit `WalletToolkit` guard.
- **D-MG-3:** correct the workflow `allowMainnet` record without changing persisted identities. STOP if it cannot be done.

## B1. Implementation

**`@hardkas/core` — new `src/mainnet-policy.ts`, exported:**
- `MAINNET_TRANSACTIONS_ENABLED = false` (constant).
- `isMainnetNetworkId(id)`: `mainnet`, `kaspa`, `kaspa-mainnet`, any case. This is the CLI guard's notion, moved to core.
- `assertMainnetTransactionsDisabled("sign" | "broadcast", networkIds[], context?)`:
  - refuses when **any** of the network identities involved is mainnet, never only the one a caller declares;
  - throws `HardkasError` `MAINNET_SIGNING_DISABLED` / `MAINNET_BROADCAST_DISABLED` with `metadata.networks`;
  - the message never suggests a flag;
  - it does not read `allowPublic`, `experimental`, the signer or the mode.

**SDK `src/tx.ts`:**
- **`tx.sign`:** right after the schema check, before every branch (v1 runtime, external signer, multisig append, internal signer) and before anything is written: `assertMainnetTransactionsDisabled("sign", [artifact.networkId, artifact.execution?.network, instance network])`.
  - The external signer is never called.
  - Workflow sign steps go through it.
- **`tx.send`:** first statement, before the simulator/real branches, any RPC request, receipt or event: `assertMainnetTransactionsDisabled("broadcast", [signed.networkId, signed.execution?.network, instance network])`.
  - An artifact signed anywhere, outside HardKAS included, is refused the same way.

**SDK `src/workflow.ts` (D-MG-3):**
- The artifact's `policy.allowMainnet` records `MAINNET_TRANSACTIONS_ENABLED` (`false`).
- The `policySnapshot.allowMainnet` that feeds `deriveWorkflowId` is **left exactly as it was** (it carries `allowPublic` under that key), documented as a frozen identity input.
- **No STOP needed:**
  - no workflowId changes;
  - no verifier recomputes the workflowId from the artifact's `policy` (only `tx-plan.ts`, `cli/tx-flow.ts` and `workflow.ts` derive one, each from its own intent);
  - historical artifacts are untouched.
- Only new workflow artifacts get a different content hash, because their recorded `policy.allowMainnet` is now true to the policy.

**`@hardkas/toolkit` `src/wallet.ts` (D-MG-2):**
- `assertNotMainnet(operation)` takes the wallet's declared `network` and the **node's own** `getBlockDagInfo().networkId` (a read, which is allowed).
- It is called first in `payMany` (so `send`), `sweep`, `consolidate` and `split`, before any planning read. It is called again in `signAndBroadcast`, before the signer.
- So the refusal is the policy, not a Generator error on an incompatible address.

**`@hardkas/accounts`:** `signTxPlanArtifact` (plan + target network) and `assertSigningNetworkAllowed` (kaspa-wasm signer) throw the typed `MAINNET_SIGNING_DISABLED` when `allowMainnet` is not `true`.
- The "Use --allow-mainnet-signing" advice is gone.
- `allowMainnet: true` remains for direct library use; no HardKAS path passes it (checked: `tx.ts` false, `dev-accounts` false, `workflow-runner` false).

**CLI:**
- `broadcast-guard.ts` uses the core assertion: typed `MAINNET_BROADCAST_DISABLED`, the stale version string gone, mismatch check unchanged.
- `tx-sign-runner.ts` refuses a mainnet plan with `MAINNET_SIGNING_DISABLED` whatever `--allow-mainnet-signing` says. The account/artifact mismatch refusal is unchanged.
- `accounts-consolidate-runner.ts`: `--execute` on mainnet is refused with `MAINNET_BROADCAST_DISABLED` with or without `--allow-mainnet`, before any batch. A dry run (planning) stays allowed.
- `ui.ts`: the submit hint no longer mentions the flag.
- Help texts:
  - `tx sign --allow-mainnet-signing` → "Mainnet signing stays refused in this release (MAINNET_SIGNING_DISABLED); the flag has no effect";
  - `accounts consolidate --allow-mainnet` → "No effect: executing on mainnet stays refused in this release (MAINNET_BROADCAST_DISABLED)".
- `docs/reference/cli.md` and `cli.generated.json` were regenerated (`docs:generate-cli`; `docs:check-cli` green).
- The docs site copies (`apps/docs/docs/reference/cli/{tx,accounts}.md`, `docs-data/cli-command-inventory.json`) were edited to the same text, because their extractor is the open APPS-DOCS-CLI-EXTRACTOR-1.

**D-MG-1:** `sdk.rpc` / kaspa-rpc are unchanged, recorded here as a low-level transport outside the product policy. They are not a safe mainnet broadcast API.

**Other direct `submitTransaction` callers reviewed** (A1 table): none reaches mainnet through a high-level path. `kaspa wallet send` is now refused by the typed signer; silver and escrow are simnet; TQ is testnet-only.

## B3. Compatibility, NNI/EA, residuals

**Compatibility:**
- New typed codes `MAINNET_SIGNING_DISABLED` / `MAINNET_BROADCAST_DISABLED`; they were untyped `Error`s or none.
- `MAINNET_CONSOLIDATION_BLOCKED` is replaced by `MAINNET_BROADCAST_DISABLED`; no test or doc pinned it.
- `--allow-mainnet-signing` (tx sign) and `--allow-mainnet` (accounts consolidate) have no effect on mainnet.
  - The former used to let synthetic `--threshold` multisig entries through on mainnet; the multisig path is now refused, as requested.
- An external signer is never called for a mainnet artifact.
- Workflow artifacts record `allowMainnet: false`. WorkflowIds are unchanged.
- Reading and planning on mainnet, and everything on testnet, are unchanged (MG-C1…C4).

**NNI + EA + MG (all qualified, none published or merged):**
- MG's checks sit at the very top of `tx.sign` and `tx.send`.
- EA's checks (`SEND_NETWORK_MISMATCH`, `endpointAuthority`) follow the signed identity check; NNI re-throws its identity refusal in the submit `catch`.
- They are independent refusals-before-effects in the same function: one manual merge.
- MG's "any identity mainnet" is a mainnet-specific discrepancy rule. Non-mainnet artifact/instance discrepancies on send are EA-I3's.
- A general sign-side artifact/instance network check (non-mainnet) is not part of this wave. It is a candidate for the integration, next to EA-I3.

**Residuals:**
- `sdk.rpc` raw submit (D-MG-1, by decision).
- The toolkit's other "simulated v1" mainnet guards are still untyped (`WALLET_*_MAINNET_BLOCKED` in the message).
- P61 toolkit defects (separate).
- The docs-site extractor (APPS-DOCS-CLI-EXTRACTOR-1).
