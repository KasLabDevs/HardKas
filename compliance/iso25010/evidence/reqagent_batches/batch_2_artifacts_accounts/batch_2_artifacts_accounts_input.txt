Requirement HK-REQ-013 states that the artifact engine must compute deterministic SHA-256 content hashes (hashVersion 5) over canonicalized JSON with NFC Unicode normalization, LF line endings, and UTF-16 lexicographically sorted keys.
Requirement HK-REQ-014 states that the artifact store must enforce write-once immutability per artifact identity and reject any attempt to overwrite an existing artifact ID with modified content using ARTIFACT_IDENTITY_CONFLICT.
Requirement HK-REQ-015 states that the artifact store must confine all file reads and writes inside the workspace directory, reject relative path traversal sequences, block symlink or junction escapes, and cap lineage graph traversal at 64 hops.
Requirement HK-REQ-016 states that the deriveTxStatus function must be a pure deterministic function that derives transaction lifecycle states from immutable submission and observation facts per observer, detecting DAG reorgs and conflicting observations.
Requirement HK-REQ-017 states that strict artifact verification must reject legacy artifacts with hashVersion 4 or lower using MIGRATION_REQUIRED unless explicitly migrated through the auditable artifact migration command.
Requirement HK-REQ-018 states that the EvidenceBatchExporter shall package transaction plans, signed transactions, receipts, and lineage proofs into tamper-evident evidence bundles that can be verified offline without a live node.
Requirement HK-REQ-019 states that the KeystoreManager must encrypt real private keys at rest using AES-256-GCM with keys derived via Argon2id (minimum 19,456 KiB memory, 2 iterations, 16-byte salt), bind identity metadata in GCM AAD, enforce 0600 file permissions, and zero derived key buffers in finally blocks.
Requirement HK-REQ-020 states that the KaspaWasmPrivateKeySigner must never return raw WASM PrivateKey pointers across boundaries, must construct a fresh WASM Transaction per input signing pass, and must reject RPC integers exceeding Number.MAX_SAFE_INTEGER.
Requirement HK-REQ-021 states that the accounts package shall support multilateral V1 transaction drafts (V1TxDraft) allowing independent preparation, per-slot signature verification, draft combination, and finalization.
Requirement HK-REQ-022 states that when loading real account stores, the system must detect legacy plaintext private keys, emit security migration warnings, and block importing or generating mainnet keys.
Requirement HK-REQ-023 states that the transaction planner and signer should support spending from ECDSA P2PK addresses (currently refused fail-closed with ECDSA_SPEND_NOT_SUPPORTED; only Schnorr P2PK spending is implemented).
Requirement HK-REQ-024 states that the transaction planner and signer should support non-zero absolute lockTime (CLTV) values on planned transactions (currently refused fail-closed with LOCK_TIME_NOT_SUPPORTED when lockTime is not 0).
