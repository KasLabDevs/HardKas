Requirement HK-REQ-025 states that standard V0 payment and consolidation plans must delegate UTXO selection, mass calculation, KIP-9 storage mass validation, and fee estimation to the official kaspa-wasm Generator and verify strict value conservation.
Requirement HK-REQ-026 states that when planning RPC transactions, the UTXO provider must query the node mempool to exclude pending-spent inputs and fail closed with PENDING_SPEND_EVIDENCE_UNAVAILABLE if mempool visibility is unavailable.
Requirement HK-REQ-027 states that the payment planner and signer must automatically exclude covenant UTXOs from ordinary payment selection and reject any attempt to spend a covenant UTXO in a V0 payment with COVENANT_UTXO_NOT_PAYMENT_INPUT.
Requirement HK-REQ-028 states that version-1 transaction plans must validate non-empty inputs and outputs, value conservation, fee ceiling bounds (maxFeeSompi), u16 compute budgets (0 to 65535), covenant group invariants, and zero embedded secrets.
Requirement HK-REQ-029 states that every planned payment must enforce a maximum fee ceiling (defaulting to 10,000,000 sompi / 0.1 KAS) and reject node fee-rate estimates exceeding maxFeeRate (default 10,000 sompi/gram) with FEE_RATE_ABOVE_BOUND.
Requirement HK-REQ-030 states that the Kaspa RPC client must verify node network identity and sync status (isSynced: true) on connect and right before broadcast, implement a 3-state circuit breaker for reads, and never auto-retry submitTransaction broadcasts.
Requirement HK-REQ-031 states that on Windows Node.js environments, the RPC transport must wrap the ws package WebSocket in GuardedWebSocket to prevent native libuv UV_HANDLE_CLOSING assertion crashes on repeated connection teardown.
Requirement HK-REQ-032 states that the managed localnet controller shall orchestrate a Dockerized rusty-kaspad v2.1.0 simnet node with container and image digest verification, automated CPU miner coinbase maturity funding, and local UTXO snapshot/restore.
Requirement HK-REQ-033 states that the in-memory simulator shall execute synthetic Kaspa transactions, GHOSTDAG topology approximations, and ScriptVM checks in sub-milliseconds while identifying itself as 2.1.0-kaspa-simulator so it is never mistaken for a real consensus node.
Requirement HK-REQ-034 states that signed V0 payment artifacts currently commit storageMass 0 by design while the node mempool computes and mines the KIP-9 storage mass under the same txId; a future versioned format should align the signed V0 artifact's storageMass field byte-for-byte with the mined transaction.
Requirement HK-REQ-035 states that the in-memory simulator is an approximate model where OpZkPrecompile and OpChainblockSeqCommit fail closed and block-level WrongMass commitment has no real-node vector; consensus-critical covenants and timelocks must be verified on Docker simnet.
Requirement HK-REQ-036 states that background localnet CPU mining should enforce a bounded block cap or target balance watchdog so unbounded mining over many hours does not accumulate hundreds of thousands of UTXOs and exceed the 100 MiB WebSocket frame limit on getUtxosByAddresses.
