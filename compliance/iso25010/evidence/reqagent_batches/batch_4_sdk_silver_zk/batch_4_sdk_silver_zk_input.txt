Requirement HK-REQ-039 states that the covenant engine shall build Toccata V1 genesis and 1:1 auth-bound state transition transactions, iteratively converge V1 compute-budget fee floors, and reconstruct historical covenant lineage from workspace artifacts.
Requirement HK-REQ-040 states that the off-chain Groth16 verifier must validate BN254 field elements, curve membership, G2 subgroup membership, weak verification-key trapdoor heuristics, and verification-key fingerprint anchoring inside an isolated child process with a 15-second timeout and concurrency cap of 4.
Requirement HK-REQ-041 states that the Toccata RISC Zero Groth16 builder must cross-check the receipt claim digest against (imageId, journalHash), enforce computeBudget >= 1550 and computeMass <= 500,000, and in proof-and-output-bound mode enforce output count, recipient SPKs, exact amounts, single input, and maxFeeSompi via L1 introspection opcodes.

Requirement HK-REQ-044 states that the bridge-local package shall serialize and deserialize L1-to-L2 bridge entry payloads and simulate deterministic prefix mining for local bridge laboratory workflows.
Requirement HK-REQ-045 states that the deprecated SDK methods HardkasCovenants.planDeploy and HardkasCovenants.planSpend currently throw COVENANT_PLAN_UNSUPPORTED at runtime and should be either implemented or removed from the public SDK surface.
Requirement HK-REQ-046 states that because a P2SH redeem script cannot commit to its own funding outpoint (ZK_UTXO_BINDING_UNSATISFIABLE) and does not parse the HKZ1 journal on-chain, repeated identical funding of a proof-and-output-bound ZK P2SH address should be protected against receipt replay by composing a Toccata V1 stateful covenant.

Requirement HK-REQ-048 states that real-node SilverScript deploy/spend execution via the high-level SDK surface (SDK_SILVER_REAL_LIFECYCLE_UNSUPPORTED) and testnet-10 certification for multi-input N:M covenant topologies should be completed beyond the current CLI localnet baseline.
