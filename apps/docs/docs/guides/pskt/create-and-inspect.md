# Creating & Inspecting PSKTs

HardKAS CLI provides a full workflow for orchestrating Portable Signing Sessions.

*Note: The `pskt` commands are currently marked as experimental while upstream `rusty-kaspa` stabilizes post-Toccata script extraction rules. You must set `HARDKAS_EXPERIMENTAL=1` in your environment.*

## 1. Exporting a Plan

Normally, `hardkas tx plan` generates a `TxPlanArtifact`. To convert this intent into a distributable PSKT, use `export`:

```bash
hardkas tx plan --from alice --to bob --amount 10 --out plan.json
hardkas pskt export --plan plan.json --out session.json
```

This creates a `PortableSigningSession` artifact containing the base64-encoded binary PSKT payload generated by the upstream native Kaspa library.

## 2. Inspecting the Payload

Before a Signer attaches their private key, they must independently verify the contents of the PSKT. Since the payload is binary, HardKAS provides an inspection tool that delegates to the upstream native decoder.

```bash
hardkas pskt inspect session.json
```

**Expected Output:**
The inspection will reveal:
* The Unsigned Transaction ID.
* The Inputs being spent (and their expected values).
* The Outputs (Recipients and Amounts).
* The current Signature State (which inputs are missing signatures).

*Security Rule:* The Signer must trust the output of `inspect`. If the outputs do not match the expected intent, the Signer must reject the PSKT.
